Properties that answer questions

A database is only as good as the questions it can answer, and every answer is decided the moment you pick a property type. Type a rate as text and no view will ever total it. Use a plain tag for project stage and no filter will ever know which projects are finished. Part 1 · covers property types

The question comes first, the type follows

5 min live

A property is a promise about what you will be able to ask later. Number promises sums and averages. Date promises "before" and "after". Status promises "is it finished?". Pick the type from the question, never from what looks quickest to type, because the wrong type looks fine for weeks and fails the first time you need an answer.

LiveThe question comes first3 min▶

Ines's homework from session 1 was five questions she asks every week. Each one names its property type almost by itself. "What will I bill this month?" needs her rate as a Number, and Notion lets a Number display as currency, so it still reads as dollars while staying a number. "Which stage is each project in?" needs Status. "Which projects used diary studies?" needs Multi-select, because a project can mix methods. "What starts or ends this quarter?" needs Date properties for start and end. "Who is doing the fieldwork?" needs Person, so Theo is a person you pick, not a word you might spell three ways.

The test for every new property is one sentence: say the question out loud, then ask whether this type can answer it without you reading every row. If it cannot, it is the wrong type, however tidy it looks today.

Self-studyAll 22 types on one page4 min▶

Notion's Database properties help page names 22 types. They sort into six kinds, and the kind tells you who fills the value in.

Values you type or pick (12): Text, Number, Select, Status, Multi-select, Date, Person, File, Checkbox, URL, Email, Phone. Number can display as currency or as a progress bar.

Values Notion records for you (5): Created time, Created by, Last edited time, Last edited by, and ID. Nobody types these, which is exactly why they can be trusted for "what changed this week?".

Computed (2): Formula and Rollup. Session 5 writes formulas; session 3 builds rollups.

Connections (1): Relation, which links a row to rows in another database. It is the whole of session 3.

Actions (1): Button, covered in session 5. Location (1): Place.

A database can hold up to 500 properties. You will never need that many; if a database is heading past a few dozen, it is usually two kinds of thing sharing one table, and session 3 shows how to split them.

Real world

The rate column that could never be summed. A familiar pattern in freelance trackers: rates typed into a text column as "$120/h", "125 an hour" and "95". Every row reads clearly to a person, and not one of them can be totalled, averaged or compared, because to the database they are words. The fix is a Number column shown as currency, retyped once. The cost of leaving it is a spreadsheet export every month to answer one sum.

Part 2 · covers select, status and multi-select

Status knows what done means

5 min live

Select, Status and Multi-select all show coloured tags, so they look interchangeable. They are not. Select holds one tag. Multi-select holds one or more. Status holds one tag that also belongs to a group, and the groups are fixed: To-do, In progress, Complete. That grouping is what lets a filter ask "is it finished?" without you listing every tag that means finished.

LiveStatus knows what done means3 min▶

Notion's help page says Status tags are grouped into To-do, In progress and Complete. Ines names her project stages to match her real work: Not started under To-do; Recruiting, Fieldwork and Synthesis under In progress; Delivered under Complete. On a board grouped by Status she sees her pipeline at a glance, and a filter can ask about the group rather than the tag names.

Select is the right choice when a property is a single label with no idea of finishing: a client's Active or Past standing, a meeting type, a reading-list topic. Multi-select is right when a row can carry several labels at once: a project that mixes interviews and a diary study carries both methods. The question decides again. "Is it finished?" means Status. "Which kind is it?" means Select. "Which kinds does it include?" means Multi-select.

Self-studyDates, created time and the ID3 min▶

Date is the type for anything you will put on a calendar or ask "before" and "after" of. Ines uses two Date properties on Projects, Start and End, so a filter can ask about either one on its own, and a calendar view can show projects by their end date.

Created time and Last edited time, with their partners Created by and Last edited by, are filled in by Notion, never by you. That makes them honest: a view sorted by Created time shows rows in the order they really arrived, which also answers the session 1 note that, above 1,000 items, new rows may appear in the middle of a database.

ID is on the same list of types Notion records for you. It is a tempting candidate for invoice numbers. How its numbers are assigned is not recorded here, so read the Database properties help page on the day before you rely on it for anything a client will see.

Pick Status over Select whenever you will ever ask "is it finished?". Projects, tasks, invoices, reading-list books: all of them finish. Switching later means retagging every row by hand, so decide on the first evening.

Part 3 · covers views, filters, sorts and groups

Filters that are yours, filters that are everyone's

5 min live

Properties make questions possible; views ask them for you every day. Each view keeps its own filters, sorts and grouping, so Ines can have a board, a filtered table and a calendar over the same project rows. One switch decides whether those settings are a private lens or the shared view everyone opens: "Save for everyone".

LiveFilters that are yours, filters that are everyone's3 min▶

Notion's views help page is precise: filter and sort changes apply only to you unless you choose "Save for everyone". That is a kindness while you explore, and a trap when you forget. Ines can narrow the Tasks table to this week, and Theo still sees every task, until she saves the view for everyone.

Simple filters stack conditions one after another. Advanced filters combine AND and OR inside filter groups, "nested up to three layers deep". Ines's "open projects" table reads: Status is not Complete, AND (End before week 13 OR Method has Diary study). In words: every unfinished project that is either ending soon or running a diary study, which tends to need longer follow-up. The week number is constructed; your own cut-off will differ.

Self-studyGroups and sub-groups3 min▶

Any view can be grouped by a property, and empty groups can be hidden so a board does not fill with blank columns. Sub-groups add a second layer: group Tasks by Status, then sub-group by priority, and each status splits into its own priority bands.

Each view keeps its own settings. That is why one database can serve several people: Ines's board, Theo's filtered table and the planning calendar each remember their own filters, sorts and groups, and none of them holds a copy of a row. Session 6 puts linked versions of these views on a single dashboard page.

Real world

The rows that were "lost". A familiar pattern in shared workspaces: someone reports that half the tasks have vanished. Nothing was deleted. A teammate added a personal filter weeks ago, forgot it, and read the narrowed table as the whole database. The check takes ten seconds: look for an active filter on the view before you assume missing data. The prevention is a habit: shared views get saved for everyone on purpose, and private narrowing happens in a view named as yours.

Check yourself

Three questions

Clear all three and session 2 gets stamped in your passport.

1 · Ines wants to know what she billed this month. Why must Rate be a Number rather than Text?

A Number shown as currency reads like dollars and still behaves like a number, so totals and averages work. Text displays fine and can be filtered by its words, but no view can add "$120/h" to "125 an hour".

2 · Ines adds a new project tag, "Paused", under In progress. Her "not finished" filter reads Status is not Complete. What happens?

Status groups every tag into To-do, In progress or Complete, so a filter on the group keeps answering as tags change. A plain Select has no groups, which is why a "done" filter built on Select must list every finished tag and breaks when one is added.

3 · Ines filters the Tasks table to this week but does not choose "Save for everyone". What does Theo see when he opens the view?

Notion keeps filter and sort changes personal unless you choose "Save for everyone". Her private lens is fine for exploring; a view meant to be shared has to be saved on purpose.

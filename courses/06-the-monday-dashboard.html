Part 1 · covers linked views

A dashboard holds views, never rows

5 min live

A dashboard is a page, and session 1 promised it would stay one. What sits on it are windows into databases that live elsewhere. Notion calls them linked databases: you type /linked, pick a database, and get a view of its rows. Edit a row through the window and the original changes, because there is only one row.

LiveA dashboard holds views, never rows3 min▶

Notion's linked databases guide gives the move in three steps: type /linked on the page, pick the database, then copy one of its existing views or create a new one. From then on, edits you make in the linked view appear in the original. The guide also draws the line that makes dashboards safe: "filters and views only apply to the linked instance".

So Ines can filter her Home copy of Tasks down to this week without touching the board she uses for planning, or the table Theo works from. Change a status in the Home panel and the task is done everywhere, because the panel never held a task. It held a question.

Self-studyLinked data sources and what travels3 min▶

The data sources help page adds the vocabulary under the hood. "Every database is made up of at least one data source", and a database can contain several. When you link a data source into another place, edits to its title, its properties or its pages are reflected in the original. Views, filters, sorts and groups you create on the linked source stay local and do not change the original's views.

Two practical consequences. If you rename a property from inside a linked view, you renamed it for everyone. And only people with Can edit access can move data sources, which matters in Part 3: the contractor you trust with task values should not be the person who can relocate the database they live in.

Real world

The status report that someone re-types every Friday. A familiar pattern in shared workspaces: a "Weekly status" page where one person copies open tasks and overdue items in from three databases by hand. It is out of date by Monday lunchtime, and nobody can tell which line is stale. Replace each pasted block with a linked view and its filter, and the report is never re-typed again: it is just right whenever someone opens it.

Part 2 · covers the four questions a Monday dashboard answers

One filter per purpose

5 min live

A dashboard fails in one of two ways: it shows everything, so nobody reads it, or it shows a clever mix nobody can explain. The cure is the same for both. Write down the question each panel answers, then give that panel exactly the filter the question needs, and nothing more.

LiveOne filter per purpose3 min▶

What is due this week? Tasks, Due within this week AND Status not Complete. Status groups its tags into To-do, In progress and Complete, so "not Complete" catches every unfinished state in one condition. What is in progress for each client? Projects, Status is In progress, grouped by the Client relation from session 3, so each client becomes a heading with its live projects under it. What is unpaid, and how much? Invoices, Status is Issued and not Paid, with the amount totalled. What am I reading? Reading list, Status is Reading.

Advanced filters combine AND and OR in filter groups, nested up to three layers deep, but a Monday panel rarely needs more than two conditions. Filter and sort changes apply only to you unless you choose "Save for everyone". Theo will open Home too, so save each panel's filter for everyone; otherwise he sees a different dashboard from the one you designed.

For the unpaid total: the help pages read for this session record Sum as a rollup calculation on number properties. A rollup cannot filter, so a per-client Sum adds paid and unpaid together. For an unpaid-only number on Clients, use the session 5 formula pattern, which can reach into related rows, keep the issued ones and add their amounts.

Self-studyCharts, and when a table is enough2 min▶

Chart is one of the view types Notion's databases page names, alongside table, board, list, calendar, gallery and timeline. That is all the help pages read for this session record about charts; settings and chart types beyond the name are not covered here, so check the current help page before you build one.

The practical rule does not depend on the feature list. When the reader needs an exact number, such as which invoice and how much, a table is the right view: a chart answers "is this going up?", a table answers "who do I email?". Monday morning is mostly the second question.

If a panel needs scrolling, its filter is too loose. A Monday panel should fit on the screen. Twenty rows under "due this week" means the filter is catching next month, or the week is genuinely overloaded; both are worth knowing before 9am.

Part 3 · covers permissions and sharing

What Theo can touch

5 min live

Theo needs to tick off recruiting tasks and add notes to them. He does not need to see what Ines charges, and he should never be able to change the filter on a view she relies on. Notion's permission levels are fine-grained enough to say exactly that, if you set them on purpose instead of sharing the whole workspace.

LiveWhat Theo can touch3 min▶

The sharing help page lists the levels: Full access, Can edit, Can edit content, Can comment and Can view, plus Can create, a database-only level that lets someone add pages without seeing anyone else's. The one built for Theo is Can edit content, which applies to databases only: he can create and edit pages and property values, but not the structure, the views, the sorts or the filters.

So Ines gives Theo Can edit content on Tasks, Can view on Projects and on Home, and nothing on Invoices. Then the inheritance rule, quoted from the page: "When you create a subpage inside of a page, that subpage will take on the permissions of its parent page." A recruiting brief Ines writes inside Home is visible to Theo the moment it exists. Anything private goes outside the pages he can see.

One gap to respect: the help pages read for this session do not say what a linked view shows to someone with no access to its source database. Do not rely on the Home panel hiding Invoices. Keep the Invoices database itself unshared, and check its Share list, not the dashboard's.

Self-studyGuests and publishing2 min▶

Guests are people outside your workspace; the help page notes they need a Notion account. A freelancer's contractor is often exactly this, which is why Theo is shared into specific pages rather than given the workspace.

Publishing is a different act from sharing. The Share menu has a Publish tab that puts a page on the web. Never publish a page that holds invoices, rates or client names, and remember that subpages created inside a page start with that page's permissions. If you want to share something public, make a new page for it outside the dashboard.

Real world

The contractor who re-sorted everybody's view. A familiar pattern in shared workspaces: a contractor given full edit rights changes a board's filter to show only their own items, and the whole team's planning view quietly loses half its cards for a week. Can edit content prevents it at the source: they can still update every value they need to, but views, sorts and filters are out of reach.

Build-along

Ines's Monday dashboard, in your own account

★ 22 min · everyone builds

Turn the Home page from session 1 into the dashboard, share one database with a contractor, and run the ritual once. Ines's values below are constructed; your clients, filters and totals will differ. If you have no contractor, share with a second email of your own to watch the permission levels work.

Add four linked views to Home. Open Home. Under the title, type /linked, pick Tasks, and create a new view. Set its filter and save it for everyone. Repeat for Projects, Invoices and Reading list. Name each view by the question it answers.

★ Step 1 · four windows, four filtersHome → /linked → Tasks → new table view Name: Due this week Filter: Due is within this week AND Status is not Complete Save for everyone Home → /linked → Projects → "In progress" Status is In progress Home → /linked → Invoices → "Unpaid" Status is Issued (not Paid) Home → /linked → Reading list → "Reading" Status is Reading (Ines's names; yours may differ)

Group the projects panel by client. In the In progress panel, group by the Client relation from session 3 and hide empty groups. Each active client becomes a heading with its live projects underneath.

★ Step 2 · projects per clientIn progress panel → Group by: Client Hide empty groups Ines sees (constructed): Aldermoor Health · Diary study, round 2 Brightwell Mutual · Pension app usability Corvid Studio · Checkout redesign test Dunmore Council · Resident survey

Add the unpaid total. Show the Amount column in the Unpaid panel so each invoice's figure is visible. For one number per client, add the session 5 formula on Clients that keeps only issued invoices and sums their amounts, because a Sum rollup would add paid ones too.

★ Step 3 · the number that mattersUnpaid panel → show property: Amount, Client, Issued date Sort: Issued date, oldest first Clients → new Formula property "Unpaid": prop("Invoices") .filter(current.prop("Status") == "Issued") .map(current.prop("Amount")) .sum() (values constructed; your totals will differ)

Share Tasks with Theo, and check Invoices stays private. Open the Tasks database, share it with Theo as Can edit content. Share Home and Projects as Can view. Then open Invoices' Share menu and confirm Theo is not listed.

★ Step 4 · Theo's accessTasks → Share → Theo → Can edit content Projects → Share → Theo → Can view Home → Share → Theo → Can view Invoices → Share → check: Theo is NOT listed Rule: anything created inside Home inherits Home's access

Put the Monday review at the top. From session 5, add a weekly repeating template in Tasks called Monday review, so a fresh review task appears every week. On Home, add a button above the panels that adds a page to Tasks, for the weeks you start early.

★ Step 5 · the ritual starts itselfTasks → New ▾ → + New template → title: Monday review Repeat: weekly · Monday · 08:30 Home (top) → button "Start Monday review" Action: Add page to → Tasks (buttons work on every plan; some actions are paid-only)

Run the 15-minute ritual once. Go round the loop in the figure, panel by panel. Archive finished projects with Status, never by deleting them: in session 4's break, deleting one client row orphaned 50 linked rows, counted on the constructed rows.

★ Step 6 · fifteen minutes1 Triage tasks (4 min) do, move, or hand to Theo 2 Projects per client (3 min) anything stalled? 3 Chase unpaid (3 min) email the oldest issued invoice 4 Archive finished (3 min) Status → Archived, never delete 5 Pick one reading (2 min) one row moves to Reading (Ines's timings, constructed)

Archive is a status, delete is a hole. An Archived project keeps its client, tasks and invoices joined up, so last quarter's totals still add up. A deleted one sits in Trash for 30 days by default and then is permanently deleted.

Check yourself

Three questions

Clear all three and session 6 gets stamped in your passport.

1 · Why put a linked view of Tasks on the dashboard instead of a copied table of this week's tasks?

Edits in a linked database appear in the original, and its filters and views apply only to the linked instance. A copy is a second set of rows, and copies drift; session 4 counted how fast. A linked view changes nobody's permissions.

2 · Theo must update task statuses and notes but never change a view's filter. Which level on Tasks?

Can edit content is database-only: create and edit pages and property values, but not structure, views, sorts or filters. Can edit and Full access would let him change the views; Can comment would not let him change a status.

3 · Ines creates a new subpage inside Home, which Theo can view. What access does Theo have to the subpage?

The help page is explicit: a subpage created inside a page takes on the permissions of its parent page. That is why private material belongs outside any page Theo can see.

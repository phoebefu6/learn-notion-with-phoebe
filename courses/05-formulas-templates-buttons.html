Part 1 · covers Formulas 2.0

Compute it, never type it

5 min live

A formula property works out its value from the row's other properties, every time you look. An amount typed by hand is a second copy of a fact the row already holds (hours times rate), and session 4 showed what second copies do. A formula is not a copy: it has no value of its own to fall out of step.

LiveThe syntax you type4 min▶

References. The syntax help page writes a property reference as prop("Name"), and that is the form to type. The editor may then display the property name inline, the way the intro page shows dateAdd(Start Date, 2, "week"); same reference, different display. Ordinary operators do the arithmetic, so an amount is prop("Hours") * prop("Billed rate").

Choices. if takes a condition, a value when true and a value when false. ifs checks pairs in order and ends with a fallback: the help page's example ifs(true, 1, true, 2, 3) returns 1, because the first true condition wins.

Names for pieces. let gives a part of the formula a name so you write it once. The help page's example: let(SalesTax, (prop("Subtotal")*0.099), prop("Subtotal") + SalesTax). lets does the same for several names at once.

Room to think. The Formulas 2.0 guide says formulas "can be written multi-line in the editor (with tabs and comments too!)", with comments written /* like this */. Use them: a formula Ines can read in six months is a formula she will not rewrite.

What comes out. Formulas used to output text, numbers and checkboxes. The guide says they now also output pages, dates, people and lists. Tonight's Amount outputs a number and Overdue outputs a checkbox. The functions on this page (if, ifs, let, lets, map, filter, sum, format, dateBetween, dateAdd, now, round, empty, contains, toNumber, style) are the ones confirmed with examples on the syntax page; the editor lists the rest.

Self-studyReaching into related rows4 min▶

The guide says formulas "can reach into properties of related databases", which means many questions that used to need a rollup can now be one formula. Its own example counts the done tasks on a project through the Tasks relation:

prop("Tasks").map(current.prop("Status")).filter(current == "Done").length()

Read it left to right: take the related task pages, turn each into its Status, keep only the ones equal to "Done", count what is left. current means "the item being looked at right now" inside map and filter.

Dot notation reads a piece of a value directly, for example prop("Created By").name() for the name of the person who made the row.

One migration note. When Formulas 2.0 arrived, existing formulas that referenced rollup, person, file and multi-select properties were converted to text. If you inherit an old workspace and a formula that should be a number behaves like text, that conversion is the first suspect.

Test as you write. Open the formula editor from a row rather than from the property header, and the help page says you get a live preview of the result for that row, with the available properties and functions listed beside it.

Real world

The amount column nobody trusted. A familiar pattern in freelance invoicing: hours in one column, a rate in another, and the amount typed in a third. Someone corrects the hours after a call and forgets the amount, and from then on the total at the bottom of the quarter is a sum of numbers that no longer equal hours times rate. Nobody can say which rows are wrong without recalculating all of them. A formula column has no such rows.

Part 2 · covers templates

A template is a stamp, not a starting page

5 min live

Every new project Ines runs needs the same few things: a kick-off call, a discussion guide, recruitment with Theo, a readout. Without a template she rebuilds that list from memory, and memory skips a step the week she is busiest. A database template is a page shape you stamp into the database, so every new row starts complete.

LiveA New project template3 min▶

The help page puts it next to the New button: open the dropdown beside New and choose + New template. The template is a page, and its title is the template's name, so call it what you will pick from the list: New project.

Inside it, put what every project needs: a checklist of the standard steps, a heading for the brief, a Status of Not started. When Ines creates a project from it, the new row arrives with all of that already written. What she adds is only what is different about this project: the name, the client, the dates.

The test for what belongs in a template is the same as session 1's test for a database, turned around: put in only what is true of every row. Anything that differs per row is a blank to fill, not a value to pre-set.

Self-studyRepeating templates and their limits3 min▶

A template can repeat: daily, weekly, monthly or yearly, with an interval, a start date and a time. In the help page's words, repeating templates "automatically create a copy of a template in your database" on that schedule. That is how Ines gets a Monday review page in her Meetings database every week without remembering to make one.

Three limits from the same page. Templates can nest at most three levels deep. There is no nesting inside a daily-repeating template. And the page advises against pre-filling relation properties unless every page made from that template should relate to the same page.

That last one is the trap. A New project template with Brightwell Mutual pre-filled as the client would quietly file every future project under Brightwell, and session 4's by-client revenue would be wrong from the first new project. Leave relations blank in templates unless the target truly never changes.

Never pre-fill the client relation in a template. A template stamps the same value on every row it makes. The client is the one thing that is different on every project, so it is always a blank you fill on the new row.

Part 3 · covers buttons and database automations

The rate that stops moving when you say so

5 min live

Session 4's winning design read the client's rate when an invoice was issued and then kept it. "When an invoice is issued" is a moment a person decides: Ines sends the invoice, and only then should the rate be fixed. A button is how you give a person's decision a single, repeatable effect.

LiveA button that freezes the rate4 min▶

A button is a property type, and the database buttons help page says a button property adds an "Edit property" action that changes pages in the current database, the row you clicked on. Another action, Define variables, creates variables from mentions and formulas that later actions in the same button can use.

Here is the design. Each invoice has a Client rate, a rollup that reads the client's current rate live, and a Billed rate, a plain number. An "Issue invoice" button does two things in one click: it sets Status to Issued, and it copies the Client rate into Billed rate. After that click, Billed rate is an ordinary number. When Brightwell's rate goes up next quarter, the Client rate on old invoices changes and the Billed rate does not, which is exactly right: the old work was billed at the old rate.

This is rung 4 of session 4's bench. Counted on the constructed rows, rung 4 left 0 stale-rate invoices and $0 off contract, against 7 stale invoices and $1,965 off on rung 3. The bench also counted the tempting shortcut: if Amount had used the live rollup directly, with nothing frozen, it would have rewritten 14 past invoices.

The exact wiring (how a variable reads the rollup, which value the Edit property action accepts) may need adjusting in your workspace; the goal is what matters. Add a Show confirmation action first, so a stray click asks "issue this invoice?" before it writes anything.

Self-studyDatabase automations and the plan line4 min▶

A database automation runs without a click. The help page lists three triggers: Page added, Property edited, and Every {frequency}. Its actions include Edit property, Add page to, Edit pages in, notifications, mail, webhook, Slack and Define variables.

The plan line, as the help page states it: database automations need a paid plan. Free plan users can create only Slack notification automations, and can use, but not edit, automations that come included in templates. Buttons are on every plan, but two button actions, Send mail (Gmail) and Send webhook, are paid-only, and Send Slack notification is listed for Plus, Business and Enterprise. Plan prices change too often to print; read the pricing page on the day you decide.

The rest of the button actions on the help page: Insert blocks, Add page to, Edit pages in, Send notification to (up to 20 members), Show confirmation, Open page or URL, and Define variables.

Anything that has to cross into another app (a form tool, an accounting package, your inbox rules) belongs to external tools such as Zapier, Make and n8n, and those are taught in Automation ↗. Notion's own buttons and automations stay on this page.

Real world

The automation that stamped the wrong date. A familiar pattern in shared workspaces: an automation set to fill "Sent on" with today's date whenever an invoice was edited. It worked the day it was built. Then someone fixed a typo in a January invoice in March, and the invoice now said it was sent in March. "Sent" was a moment a person decided, so it needed a button, which runs once when clicked, not a trigger that runs on every edit.

Build-along

The invoice engine, in your own account

★ 22 min · everyone builds

Tonight the Invoices database stops being a list of typed numbers. You will add two formulas, a live rate, a frozen rate and the button between them, then two templates. Ines's values are constructed; your rates will differ. Steps 1 to 5 work on a free plan; nothing here needs a paid automation.

Add the Amount formula. In Invoices, make sure Hours and Billed rate exist as Number properties (type a rate into Billed rate by hand for now; step 4 takes over that job). Then add a Formula property called Amount. Open the editor from one row so you see the live preview.

★ Step 1 · AmountInvoices → add property → Number: Hours Invoices → add property → Number: Billed rate Invoices → add property → Formula: Amount /* hours times the rate frozen at issue */ prop("Hours") * prop("Billed rate") Check on Ines's INV-031: 12 x 125 = 1,500 (constructed)

Add the Overdue formula. It should be true only when the invoice is not Paid and its due date has passed. If Invoices does not yet have a Due date (Date) and a Status with a Paid option, add them first. This version uses only functions confirmed on the syntax page.

★ Step 2 · OverdueInvoices → add property → Formula: Overdue /* paid or undated invoices are never overdue */ ifs( prop("Status") == "Paid", false, empty(prop("Due date")), false, dateBetween(now(), prop("Due date"), "days") > 0 ) Check: an Issued invoice due last week shows ticked

Add the Client rate rollup. You cannot roll up a rollup, so a rate rolled up onto Projects cannot be rolled up again onto Invoices. Two ways round it: put the rate rollup on Projects and have the invoice formula read that, or relate Invoices directly to Clients. Pick the direct relation, limited to one page, because an invoice has exactly one client.

★ Step 3 · a live rateInvoices → add property → Relation → Clients Name: Client · Limit: 1 page Show on Clients: on (Clients get an Invoices list) Invoices → add property → Rollup: Client rate Relation: Client · Property: Rate · Calculate: Sum (with one related client, Sum is simply that client's rate) Check: INV-031 shows 140, Brightwell's rate today (constructed)

Add the Issue invoice button. Add a Button property. Give it a confirmation first, then a variable that reads the Client rate, then one Edit property action that sets Status and Billed rate together. The exact wiring may need adjusting in your workspace; test it on a draft invoice before a real one.

★ Step 4 · freeze the rateInvoices → add property → Button: Issue invoice Action 1 Show confirmation: "Issue this invoice?" Action 2 Define variables: rate = this page's Client rate Action 3 Edit property (this page): Status → Issued Billed rate → rate Test: click on INV-046 (draft), then change Aldermoor's rate in Clients. Client rate moves; Billed rate must not.

Add a New project template. In Projects, open the dropdown next to New and make a template. Its title is its name. Put in only what is true of every project, and leave the Client relation empty.

★ Step 5 · New projectProjects → dropdown next to New → + New template Title: New project Status: Not started Client: (leave empty) Body: ## Brief ☐ Kick-off call ☐ Discussion guide ☐ Recruit participants with Theo ☐ Readout Test: New → New project, name it "Brightwell round 2"

Add a weekly repeating Monday review. In Meetings (or a Reviews database if you keep one), make a second template and set it to repeat weekly. From then on a fresh review page appears every Monday morning without anyone making it.

★ Step 6 · a page every MondayMeetings → dropdown next to New → + New template Title: Monday review Body: ☐ Unpaid invoices ☐ Tasks due this week ☐ What Theo needs from me Repeat: weekly · interval 1 · start next Monday · 09:00 (no nested templates inside it; your times will differ)

Write a one-line comment at the top of every formula. /* hours times the rate frozen at issue */ costs five seconds tonight and saves the half hour of reverse-engineering when you, or Theo, open it next year.

Homework

Before session 6

30 min
  1. Prove the freeze. Issue one invoice with the button, then raise that client's rate in Clients. Write down what Client rate and Billed rate show afterwards. If Billed rate moved, the button is copying a live value; fix the wiring.
  2. Count done tasks with one formula. On Projects, add a formula using the guide's example, prop("Tasks").map(current.prop("Status")).filter(current == "Done").length(), renamed to match your own properties.
  3. Find one typed number that should be a formula. Look through your databases for a value worked out by hand from other values on the same row, and replace it with a formula. Keep the old column for a week and compare.
  4. Sort your automation wishes. List three things you wish happened by themselves. Run each through the button, automation or neither tree, and note which ones your plan allows.
Check yourself

Three questions

Clear all three and session 5 gets stamped in your passport.

1 · Why is Billed rate a plain number set by a button, rather than a live rollup of the client's rate?

The rate in force when the work was billed is its own fact. Counted on session 4's constructed rows, a live rollup with no freeze would have rewritten 14 past invoices; the frozen rate left 0 stale invoices. A, B and D are not what the help pages say.

2 · Theo is on a Free plan. Which of these can he do?

The help page says database automations need a paid plan, except that Free users can create Slack notification automations and can use, not edit, automations included in templates. Send webhook is a paid-only button action.

3 · Which formula counts the done tasks on a project through its Tasks relation?

D is the Formulas 2.0 guide's own example: turn each related task into its Status with map, keep the ones equal to "Done" with filter, then count with length. The others do not reach through the relation.
